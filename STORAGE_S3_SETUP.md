# ☁️ НАСТРОЙКА ЗАГРУЗКИ В TIMEWEB S3

## ✅ ЧТО БЫЛО СДЕЛАНО

Все загрузки файлов (фото, документы) теперь автоматически идут в облачное хранилище Timeweb S3 вместо локальной папки `public/uploads`.

### Обновлённые файлы:

1. **`src/lib/storage.ts`** - Новый helper для загрузки в S3
   - `uploadImage()` - загрузка изображений
   - `uploadDocument()` - загрузка документов  
   - `uploadVoice()` - загрузка голосовых сообщений
   - Автоматически использует S3 если настроены переменные окружения

2. **`src/app/api/upload/route.ts`** - Основной endpoint загрузки
   - Используется при завершении задач и чеклистов
   - Теперь грузит в S3 через `uploadImage()`

3. **`src/app/api/photos/upload/route.ts`** - Загрузка фотоотчётов
   - Используется для массовой загрузки фото
   - Теперь грузит в S3 через `uploadImage()`

4. **`src/app/api/reporting/tasks/[id]/attachments/route.ts`** - Вложения к задачам отчётности
   - Используется для прикрепления файлов к задачам
   - Теперь грузит в S3 через `uploadImage()`

5. **`package.json`** - Добавлены зависимости:
   - `@aws-sdk/client-s3` - для работы с S3
   - `@supabase/supabase-js` - для Supabase Storage (опционально)

## 🔧 КАК ЭТО РАБОТАЕТ

### Автоматическое определение хранилища:

```typescript
// 1. Если настроены S3_* переменные → загружает в Timeweb S3
if (process.env.S3_ACCESS_KEY_ID && process.env.S3_BUCKET_NAME) {
  // Загрузка в облако
}

// 2. Иначе → fallback на локальное хранилище (только для разработки)
else {
  // Сохранение в public/uploads
}
```

### Формат URL файлов:

**В продакшене (Timeweb S3):**
```
https://s3.twcstorage.ru/8debacce-ce0f80be-7d86-4ccb-8c94-8f8db08667fc/photos/1731915234567-abc123.jpg
```

**В разработке (локально):**
```
/uploads/photos/1731915234567-abc123.jpg
```

## 🔍 ОСОБЕННОСТИ

### Telegram файлы

Файлы из Telegram (голосовые, фото, документы) **НЕ загружаются в S3**, так как они уже хранятся на серверах Telegram. В БД сохраняются прямые ссылки на Telegram API:

```
https://api.telegram.org/file/bot8262421888:AAH.../voice/file_123.oga
```

Это правильное поведение и не требует изменений.

### Локальный fallback

Если S3 не настроен или произошла ошибка загрузки, файлы автоматически сохраняются локально в `public/uploads`. Это удобно для разработки, но **НЕ рекомендуется для продакшена**.

### Структура папок в S3

```
bucket/
├── photos/          # Фотографии (из задач, фотоотчётов)
├── documents/       # Документы
└── voice/           # Голосовые сообщения (если будут загружаться)
```

## 🆘 УСТРАНЕНИЕ ПРОБЛЕМ

### Ошибка: "Cannot find module '@aws-sdk/client-s3'"

**Решение:** Установите зависимости:
```bash
npm install
```

### Файлы всё ещё сохраняются локально

**Причины:**
1. Не установлены зависимости → `npm install`
2. Не настроены переменные S3 в `.env` или Vercel
3. Приложение не перезапущено после изменений → `npm run dev`

**Проверка:**
```bash
# Проверьте, что переменные загружены
node -e "console.log(process.env.S3_BUCKET_NAME)"
```

### Ошибка загрузки в S3

**Проверьте:**
1. Правильность ключей доступа S3
2. Существование bucket в Timeweb Cloud
3. Права доступа к bucket (должны быть права на запись)

**Логи:**
Смотрите консоль сервера - там будут детали ошибки и автоматический fallback на локальное хранилище.
