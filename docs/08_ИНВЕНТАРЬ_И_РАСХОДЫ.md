# 8. ИНВЕНТАРЬ И РАСХОДЫ

Раздел **«Инвентарь»** в веб-приложении показывает финансовый отчёт по объектам: лимиты, фактические траты и остатки. Все действия выполняются прямо из карточек объектов — отдельного списка складских позиций больше нет.

📸 [СКРИНШОТ: Главный экран отчёта по инвентарю]

---

## 8.1 Роли и права

| Роль | Возможности |
| --- | --- |
| **ADMIN** | Видит все объекты, редактирует лимиты, заводит категории, добавляет расходы и массово обновляет лимиты. |
| **DEPUTY_ADMIN** | Работа только с назначенными объектами: выставление лимитов, добавление расходов, создание категорий. |
| **MANAGER** | Видит отчёт по своим объектам, может добавлять расходы и видеть предупреждения, но не создаёт категории и не меняет чужие лимиты. |
| **ACCOUNTANT** | Имеет доступ только к разделу инвентаря. |
| **CLIENT** | Нет доступа к отчёту. |

Каждое действие проходит серверную проверку: менеджер не может редактировать чужой объект, а заместитель — объект вне своих назначений.

---

## 8.2 Навигация и фильтры

Верхняя панель отчёта содержит:

1. Заголовок и подпись «Лимиты, расходы и остатки по объектам».
2. Переключатели **месяц / год** — формируют параметры `month` и `year` для API `/api/inventory/financial-report`.
3. Кнопку **«Массовые лимиты»** — открывает модальное окно для одновременного выставления лимитов по нескольким объектам.
4. Поиск по названию или адресу объекта.
5. Четыре сводные карточки: *Общий лимит*, *Потрачено*, *Остаток*, *Превышения*.

📸 [СКРИНШОТ: Верхняя панель и сводные карточки]

---

## 8.3 Карточка объекта

Каждый объект отображается отдельной карточкой:

- название и адрес;
- бейдж **«В пределах лимита»** или **«Превышение»**;
- значения «Лимит», «Потрачено», «Остаток» с цветовой подсветкой;
- прогресс-бар использования лимита и процент;
- кнопки действий: **«Лимит»**, **«Расход»**, **«Подробно»**.

📸 [СКРИНШОТ: Карточка объекта с действиями]

---

## 8.4 Кнопка «Лимит»

Открывает модальное окно редактирования лимита для выбранного объекта.

Поля:

1. **Категория расходов.** Список берётся из `/api/expense-categories?activeOnly=true`. Админ и заместитель могут создать новую категорию прямо в модалке (название + описание).
2. **Тип периода.** DAILY, MONTHLY, SEMI_ANNUAL, ANNUAL. Период определяет логику пересчёта.
3. **Сумма лимита.** Обязательное поле в рублях.
4. Дополнительные настройки:
   - MONTHLY: флажок «повторять каждый месяц» + выбор месяца/года окончания серии;
   - SEMI_ANNUAL / ANNUAL: дата начала, конечная дата рассчитывается автоматически;
   - DAILY: отдельный флажок «повторять ежедневно».

Сохранение делает `POST /api/objects/{objectId}/expense-limits`. После ответа карточка обновляется без перезагрузки.

📸 [СКРИНШОТ: Модальное окно редактирования лимита]

---

## 8.5 Кнопка «Расход»

Позволяет зафиксировать расход за выбранный месяц.

- Выберите категорию (опционально) и укажите сумму.
- Система автоматически подставляет объект, месяц и год из текущей карточки.
- При попытке превысить лимит сервер возвращает флаг `limitExceeded` и текст предупреждения. Запись создаётся, но карточка подсветит превышение.

Запрос отправляется на `/api/inventory/expenses`. После успешного ответа данные карточки обновляются.

📸 [СКРИНШОТ: Модальное окно добавления расхода]

---

## 8.6 Кнопка «Подробно»

Открывает диалог аналитики с двумя вкладками:

1. **Общее.** Компонент `ExpenseChart` строит график трат по месяцам для объекта.
2. **По статьям.** Показывает суммарные показатели и карточки категорий с лимитами, остатками и процентами.

📸 [СКРИНШОТ: Аналитика «Подробно»]

---

## 8.7 Работа с категориями во вкладке «По статьям»

- Для годовых и полугодовых лимитов отображается общая сумма и эквивалент на месяц.
- Для месячных и дневных лимитов показывается текущая сумма и кнопка **✏️** для редактирования.
- Проценты ≥ 90% подсвечиваются жёлтым, ≥ 100% — красным.
- Можно:
  1. Нажать **✏️** в блоке «Потрачено» — появится модальное окно корректировки суммы (создаётся компенсирующий расход).
  2. Нажать **✏️** в блоке лимита — открыть упрощённое окно изменения суммы лимита.

Все изменения фиксируются через API `/api/expense-limits/{id}` или `/api/inventory/expenses` (для корректировок).

---

## 8.8 Массовые лимиты

Кнопка в правом верхнем углу открывает форму `BulkLimitModal`:

1. Выберите категорию и тип периода.
2. Задайте сумму.
3. Отметьте объекты галочками.
4. Для MONTHLY задайте месяц/год и по желанию включите автоповтор.
5. Для SEMI_ANNUAL/ANNUAL укажите дату начала (конец считается автоматически).

После сохранения отправляется `POST /api/inventory/bulk-limits`, карточки обновляются и модалка закрывается.

## 8.9 Статусы и предупреждения

- **Бейджи**: серый — всё в порядке, красный — превышение.
- **Progress bar**: голубой внутри лимита, красный при превышении.
- **Всплывающие предупреждения**: если расход приближает объект к лимиту, сервер присылает текст предупреждения, который отображается над формой.
- **Сводка «Превышения»** показывает количество объектов, где `balance < 0`.

---

## 8.10 Типовые сценарии

1. **Настроить лимит на новый объект.** Откройте карточку → «Лимит» → выберите категорию → укажите сумму и период → сохраните.
2. **Отслеживать превышения.** Используйте фильтры месяца/года и столбец «Превышения» на дашборде. Карточки с превышениями подсвечиваются красным.
3. **Исправить ошибочный расход.** Во вкладке «По статьям» нажмите ✏️ в блоке «Потрачено» → укажите верную сумму → система создаст корректирующий расход.
4. **Выставить лимиты на сезон.** Нажмите «Массовые лимиты», выберите категорию, период (например, SEMI_ANNUAL) и нужные объекты, затем сохраните.

---

## 8.11 Советы по коррекции данных

- Любые изменения попадают в аудит (`AuditLog`), поэтому исправления прозрачны.
- Если лимит выставлен неверно, его можно переоткрыть через кнопку «Лимит» и изменить сумму или удалить запись через API.
- Расходы редактируются только через корректирующие записи — прямого редактирования нет.
- Лимиты разных типов суммируются: например, дневной лимит + годовой запас. Остаток карточки учитывает все активные периоды.
