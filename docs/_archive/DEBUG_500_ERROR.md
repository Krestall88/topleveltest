## 🔧 ВОЗМОЖНЫЕ ПРИЧИНЫ ОШИБКИ 500

### 1. S3 не настроен или неверные ключи

**Проверка:**
```bash
npm run check-s3
```

**Решение:**
Добавить/исправить в `.env`:
```env
S3_ACCESS_KEY_ID=your-access-key
S3_SECRET_ACCESS_KEY=your-secret-key
S3_BUCKET_NAME=your-bucket-name
S3_REGION=ru-1
S3_ENDPOINT=https://s3.twcstorage.ru
```

### 2. Проблема с доступом к S3 bucket

**Симптомы:**
```
❌ Ошибка загрузки в S3: AccessDenied
```

**Решение:**
- Проверить права доступа к bucket
- Проверить что bucket существует
- Проверить что ключи доступа действительны

### 3. Проблема с типом файла

**Симптомы:**
```
❌ STORAGE: Неверный тип файла: [тип]
```

**Решение:**
- Убедиться что загружается изображение
- Проверить MIME-тип файла

### 4. Файл слишком большой

**Симптомы:**
```
❌ STORAGE: Файл слишком большой: [размер]
```

**Решение:**
- Максимальный размер: 10MB
- Сжать изображение перед загрузкой

### 5. Проблема с базой данных

**Симптомы:**
```
✅ Файл загружен в S3: [URL]
❌ API: Ошибка загрузки файла: [ошибка БД]
```

**Решение:**
- Проверить подключение к БД
- Проверить схему таблицы `PhotoReport`

## 📊 ВРЕМЕННОЕ РЕШЕНИЕ: Локальное хранилище

Если S3 не работает, система автоматически переключится на локальное хранилище.

**Файлы будут сохраняться в:**
```
public/uploads/photos/
```

**URL файлов будет:**
```
/uploads/photos/filename.jpg
```

**Важно:** Локальные файлы не будут доступны после деплоя!
